UV補正モデル 実験レポート

2026-04-10 ／ RTX 5080 ／ PyTorch 2.10 (cu128)

1. 問題設定

LiDAR点群とカメラ画像の間には、取り付け誤差やキャリブレーションのズレによって 均一な平行移動オフセットが生じる。 このオフセットを画像と点群から推定する最小のToy Problemとして本実験を設計した。

  • 入力画像: (B, 1, 128, 128)、黒背景に白い矩形または円
  • 入力点群 distorted_uv: (B, 256, 2)、図形内にランダムサンプリングした後、全点に同一の(tx, ty)を加算（最大±15ピクセル）
  • 目標: 点群を元の位置に戻すオフセット (tx, ty) を推定する

2. モデルアーキテクチャ

特徴次元 D=128 の Coarse-to-Fine Cascaded Cross-Attention。

CNN バックボーン

画像から2段階の特徴マップを抽出する。

  • Coarse feature: (B, 128, 16, 16)、stride=8相当
  • Fine feature: (B, 128, 32, 32)、stride=4相当
  • 両マップに2D Sinusoidal Positional Encoding（座標系: [0,1]）を加算

Point MLP

UV座標を[0,1]に正規化してからD次元に射影する。2 → 64 → 128 → 128。

Cascaded Cross-Attention

  1. Coarseフィーチャに対してCross-Attention → offset_coarseを推定
  2. 点群を offset_coarse でワープ
  3. Fineフィーチャに対してCross-Attention → offset_fineを推定
  4. 最終出力: offset_coarse + offset_fine

重要な設計ポイント: オフセット予測ヘッドは concat(attention_output, uv_position) を入力とする。 Attention出力だけでは「どこにいるか」が分からず差分を計算できないため、 クエリ点の位置を明示的に条件付けする。

また、全N点の予測を平均してブロードキャストすることで、 「均一シフト」という問題構造をアーキテクチャレベルで強制する。

4. 失敗と原因分析

失敗① 歪み方が現実と違う

最初の実装では、各点に低周波フーリエ基底による滑らかな局所歪みを加えていた。 これはLiDAR-カメラキャリブのモデルとして不適切であり、問題を不必要に難化させていた。
→ 修正: 全点に同一(tx, ty)を加える均一シフトに変更

失敗② 深刻なオーバーフィット (train=2.1 / val=7.5)

学習データのseedが固定（base_seed + idx）だったため、 モデルが8000サンプルを丸暗記してしまい、汎化できなかった。
→ 修正: 学習時はエポックごとにランダムseedで新規サンプルを生成

失敗③ モデルがシフトを過小評価 (pred≈25%のGT)

Cross-Attentionのオフセットヘッドが Linear(D, 2) だけだったため、 「Attention出力（画像側の特徴位置）」と「クエリ点の現在位置」の差分を計算できなかった。 モデルが見ているのは画像特徴のみで、「今どこにいるか」の情報がなかった。
→ 修正: ヘッドを Linear(D+2, 2) に変更し、UV座標を明示的に入力

6. 考察・まとめ

均一シフトという単純な問題設定においても、 アーキテクチャに位置情報の条件付けがなければ正しく学習できないことが確認された。 「どこから動かすか」をモデルに明示的に伝えることが本質的な鍵だった。
