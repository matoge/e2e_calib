Raw data format (kamikado)

A "frame" = three files sharing an integer index N. A "scene" is a directory of frames with one shared calib.calib. Both POST /api/calibrate_scene and /api/calibrate_frame consume exactly this trio. Server reference parser: scripts/data/adapters/kamikado.py.

FileFormatContents / units
image_N.png PNG (JPEG also accepted on upload) full raw camera image, 3840×2160 RGB, fisheye (ip664). No crop.
points_V_N.txt plain text, whitespace-separated, lines starting with # ignored 4 columns per line: x y z intensity.
x y z are LiDAR points in the vehicle (V) FLU frame, in metres (X-forward, Y-left, Z-up).
intensity is the raw ip664 value (≈ 0–96, /128 quantum); the adapter divides by 128 and clips to [0, 1] before feeding the model.
calib.calib JSON camera intrinsics + V → camera extrinsic. Schema below.

Sample points_V_N.txt:

# x y z intensity
0.0279306112724873  8.716605133179449  0.06962442470270619  0
0.06262497844639636 8.731429248068375  0.06715762495165911  0
...

Schema of calib.calib (only the fields the server reads are shown; ordering and any additional keys are tolerated):

{
  "calibration": {
    "intrinsics": {
      "camera_model": {
        "type": "pinhole(1)",
        "pinhole_parameters": {
          "matrix_image_camera": {
            "matrix": [   // 3×3, COLUMN-MAJOR (server applies .T to get K)
              [ fx,    0,   0 ],
              [  0,   fy,   0 ],
              [ cx,   cy,   1 ]
            ]
          }
        }
      },
      "distortion_model": {
        "type": "generic_fisheye(4)",
        "generic_fisheye_parameters": {
          "coefficients": [ k1, k2, k3, k4 ]   // Kannala-Brandt equidistant, 4 coeffs
        }
      }
    },
    "extrinsics": {
      "transform_VS": {     // V (vehicle FLU) → S (sensor/camera) rigid transform
        "so3":         { "x": qx, "y": qy, "z": qz, "w": qw },
        "translation": { "matrix": [[ tx, ty, tz ]] }   // metres
      }
    }
  }
}

Pipeline applied server-side (identical to the cache builder): pts_S = T_SV · pts_V with T_SV = inv(T_VS); (u,v) = KannalaBrandt(K, dist, pts_S); points with z_S < 0.5 m or outside the image are dropped before tiling.

Wire format / response geometry

Each calibrate response also returns parent_url, parent_size, and three uv_gt / uv_pert / uv_corr arrays (N × 2, parent-image px) plus matching z_* arrays so a client can render the projection itself — exactly what powers the Konva canvas above. The arrays are packed back-to-back as little-endian float32 in the geom_url blob, in the order uv_gt | uv_pert | uv_corr | z_gt | z_pert | z_corr.

Examples

curl — server-side scene (no upload, just pick scene/frame):

curl -s -X POST http://172.16.200.185:8082/api/calibrate_scene \
  -H "Content-Type: application/json" \
  -d '{"scene":"points_ip664_D_20260226_224648_d005_3000_3020",
       "frame":0,
       "ypr":[0.3,-0.2,0.5], "t":[0.030,-0.020,0.040],
       "cs":256}'

curl — upload your own frame (image + points_V + calib.calib):

curl -s -X POST http://172.16.200.185:8082/api/calibrate_frame \
  -F "image=@image_0.png"            \
  -F "points=@points_V_0.txt"        \
  -F "calib=@calib.calib"            \
  -F 'ypr=[0.3,-0.2,0.5]'            \
  -F 't=[0.030,-0.020,0.040]'        \
  -F "cs=256"                        \
  -F "scene_id=mycar"                \
  -F "frame_id=0"
