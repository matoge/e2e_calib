One head that learns
“where does this 3D point land in another frame?”

CalibNetDepth learned "intra-frame, cross-modal misalignment"; this work generalizes it to "arbitrary-frame, arbitrary-modality misalignment". Trained symmetrically with a dual projection loss. The foundation for super-long-baseline pose estimation without bounding boxes or prior maps.

What is this problem — From classics to the present

"Where does this 3D point appear in another camera frame's image?" — This is one of the oldest questions in image processing. A one-line genealogy:

  • Classics (1980s–2010s): Lucas–Kanade solves locally using temporal brightness gradients, SIFT / ORB / KLT match keypoints with hand-designed descriptors. Hand-crafted assumptions—brightness constancy, small displacement, sufficient texture— any of which fail in the field.
  • CNN-flow / learned descriptors (2018–2022): PWC-Net / RAFT regress dense optical flow, SuperPoint + SuperGlue offer learned descriptors + attentional matching. Global context helps; performance no longer drops as sharply when baseline grows. But image × image only — no 3D.
  • Transformer correspondence (2021–2025): LoFTR offers detector-free coarse-to-fine self/cross-attn, MatchFormer goes full Transformer. LightGlue accelerates SuperGlue. DKM / ROMA regress dense warps via Gaussian Process / robust loss and output match-confidence. Recent MASt3R / DUSt3R directly regress image pairs to 3D pointmaps. All image × image. No LiDAR or depth priors.
  • Deep SLAM / VO (2021–2024): DROID-SLAM injects per-pixel learned confidence into dense BA — closest to us philosophically. DPVO uses sparse patch-graph, NeRF-SLAM / SplaTAM / MonoGS / Gaussian-SLAM adopt 3DGS as map representation and drive pose via rendering loss. All image-only; no LiDAR.
  • LiDAR–Camera correspondence (2021–2024): DeepI2P classifies "in/out of frustum", CorrI2P / I2D-Loc / EFGHNet / CFNet regress 3D–2D correspondence. Closest lineage, but all stop at single-frame calibration — no cross-frame, no output Σ (2×2 covariance directly usable as Mahalanobis weight in BA).
  • Uncertainty-aware matching (2022–2024): PixLoc / PDC-Net+ output scalar confidence, DROID-SLAM per-pixel weight, some keypoint detectors output aleatoric 2D Gaussians. No published head combining cross-modal × cross-frame × BA-ready Σ.
Gap: A learned head that takes (LiDAR 3D point + another frame's image patch) and outputs per-point (Δu, Δv, Σ2×2) in a form directly usable as Mahalanobis weight in BA does not exist in published prior work as of April 2026. CorrI2P is conceptually close but stops at single-frame calibration. DROID-SLAM is close philosophically but image-only. The intersection — cross-modal × cross-frame × BA-ready Σ — is vacant.

However, we do not consider this gap a special invention just because "no one has done it yet". All components are public: pulling image features with cross-attn, training with 2D Gaussian NLL, efficiency via deformable sampling, symmetric training with dual direction. Anyone can assemble them — AI can too. In 1–2 years the same head will appear somewhere.

What matters is the "map" built with this head. Methods can be borrowed from outside, but the map — and the system that keeps building it — must be built in-house.

Why "maps" directly impact company survival

HD maps and 3D-labeled data are common raw materials for autonomous driving / ADAS / robotics / road infrastructure inspection. As of 2025, these raw materials are produced at a cost of tens to hundreds of dollars per km, and require re-collection and updates for each country/city — a market where the competition is not one-shot but continuous unit economics. In other words, the business is determined not by "one paper" but by "cost per km × update frequency".

  • Crush cost structure via automation: Current annotation · calibration · 3D map creation is labor-cost dominated. This head solves 3D bbox propagation · calib · BA · dynamic-object σ estimation in a single function, unifying processes that previously required separate teams. Cost per km drops monotonically.
  • Update instead of re-collection: σ-weighted BA yields differential poses, so only changed areas need GS re-optimization (non-rigid update). Goal: refresh one city's map with one new vehicle's drive data. While competitors full re-scan the same area monthly, we roll incremental updates.
  • Aligns with subscription revenue: Maps are not "sell and done"; freshness is value, so monthly license · API metered billing fits. Lifetime value (LTV) differs from one-and-done paper models.
  • Data flywheel: Customer vehicle drives → differential collection → σ anomaly detection → map update → distribute to customer. Coverage and freshness improve as customers grow, so switching cost kicks in later. Organizations with only methods but no in-house fleet or subscription customers cannot enter this loop.
  • OmniRe / GS maps are reusable: Maps are not just localization databases but also simulation substrates (parked vehicles, intersections, backlight) → horizontal expansion: synthetic data sales for AV training, insurance risk assessment, urban planning visualization.

In short: methods asymptote to zero value the moment they are published, but maps with field data × automated pipeline × continuous updates drop in unit cost and rise in freshness the more you build — this is the only asymmetry that sustains a company. Papers and benchmark numbers are tools; improving unit economics is the metric that actually wins.

How this head impacts downstream tasks — this head is the foundation block for building everything we need next:
  • Build accurate data: When propagating 3D bbox / segmentation frame-to-frame, use correspondence σ as threshold to drastically cut manual review. Dynamic objects naturally have large σ, preventing false propagation.
  • Automate calibration: LiDAR ↔ Camera / Camera ↔ Camera / time sync. Just optimize the same residual function over pose. No prior maps or markers required.
  • Prerequisite for physics simulation: OmniRe / Gaussian Splatting training requires 10 Hz precision pose + calibration. Manual tuning takes 10 min/scene; this network achieves it in seconds.
  • High-precision maps with GS: Bundle poses from σ-weighted BA into mapping, inject σ directly into Gaussian opacity / sharpness priors. The learned fact that dynamic objects have large σ directly helps GS dynamic-object removal.

Story so far —— In the prior report, CalibNetDepth outputs per-point 2D Gaussian residuals for LiDAR point cloud × image, in a form usable as Σ-weighted constraints in BA. In the prior report (deform), we replaced attention and cut val NLL from 2.074 → 1.568.

This report —— The same residual formulation extends directly to cross-frame. LiDAR with 3D points, and the camera frame where they project. Apply a hypothesis pose, and residuals emerge. The net learns only the residual-prediction function, without knowing "which frame". Because the metric is the same, modalities are independent, and scale is free, single-frame calibration / VO / long-range loop closure collapse into special cases of one head.

Formulation

The learning task is equivalent to learning the same function f for cross-modal calibration / cross-frame matching / VO / loop closure:

f : (image_B patch, 3D point P_A in frame_A, pose hypothesis T̂_AB) → (Δu, Δv, Σ) s.t. π_B(T_AB^gt · P_A) = π_B(T̂_AB · P_A) + (Δu, Δv)

Inputs are independent of which frame:

  • image_B patch — just an image crop
  • P_A — 3D point (any coordinate system, as long as consistent with T̂_AB)
  • T̂_AB — hypothesis relative pose (6-DoF)

From the network's view, the concept of baseline does not exist. Whether A and B are 1 m or 200 m apart does not appear in the input. The same function f applies to both (as long as domain gap is bridged).

Data: how pair residuals are generated

One training pair = (patch_A, patch_B, uvd_A, uvd_B, pose_AB_hat, target residual). Concrete generation flow:

  1. Pair selection: From PandaSet 39 scenes, pick one scene randomly from the 31 train scenes. Then pick frame_A and frame_B = frame_A ± baseline (1–20 frames; 1 frame=0.1s) randomly.
  2. Pivot selection: From all visible LiDAR points in frame_A (~100k), randomly pick one point as pivot.
  3. Pose perturbation: T_AB_hat = T_AB_gt × δT, where δT is Gaussian with σ_ypr=1.0° / σ_t=0.2m. This simulates "dead-reckoning uncertainty".
  4. Patch cropping: Randomly choose crop size 128–256 px. patch_A crops frame_A's image centered on pivot; patch_B crops π_B(T_AB_hat · pivot_3D) (= pivot's hypothesis projection in B) as center. Both are resized to 64×64 → network input.
  5. Reject out-of-frame pivot: If pivot's hypothesis projection and GT projection in B are not both within B's image, reject the pair (out-of-frame is uncorrectable).
  6. Pivot must be patch center: If crop near image edge, zero-pad to extrapolate. This preserves the invariant that pose_emb can assume "pivot = patch center" (clipping shifts crop position, breaking pose_emb semantics).
  7. Target residual: All A's LiDAR points (~200-300) that fall within patch_A are projected to B with GT → uv_gt, with hypothesis → uv_hat. Δ_target = uv_gt − uv_hat (in patch-local px). The net predicts this Δ.

Pairs with perturbation: leak verification + residual semantics

Critical correctness check: During training, patch_B is cropped centered on hypothesis projection (π_B(T_AB_hat · P_A)) — not GT projection (π_B(T_AB_gt · P_A)). If we cropped centered on GT projection, the answer would always land at patch center, causing self-supervised leakage that breaks training.

Under perturbation σ_ypr=1° / σ_t=0.2m, render both red ★ (hypothesis position, patch center) and blue ★ (GT position) on B patch:

What the model sees in this setup:

  • patch_A: image from frame_A centered on pivot — "point was here"
  • patch_B: image from frame_B centered on hypothesis projection — "point should be here under hypothesis"
  • pose_emb(T_AB_hat): hypothesis pose 6DoF embedded to D-dim vector
  • uvd_A, uvd_B: patch-local coords + depth of all LiDAR points falling in both patches

Δtarget = uv_gt − uv_hat (patch-local px, red→blue vector in figure above) is the learning target. Model compares image content around red★ (where it should be under hypothesis) with patch_A's appearance, and outputs Δ like "true answer is X pixels down-right".

Intra-frame: concat + self-attn

Prior CalibNetDepth used "pt (Q) → img (KV) cross-attn". This is unidirectional — image does not receive pt information. Instead, here we concat pt tokens and image tokens, then apply self-attn, and split back to original roles afterward:

tokens = concat(pt_tok, img_tok) # (N_pt + H·W, D) tokens = SelfAttnStack(tokens) # symmetric modality fusion pt_tok = tokens[:N_pt] # pt that absorbed img info img_tok = tokens[N_pt:] # img that absorbed pt info

Image uses coarse features only (64×64 input → 8×8 = 64 tokens). Fine is unnecessary in this design where KV-side sparsity is not an issue for cross-frame. A/B both frames share weights (same encoder, same self-attn blocks).

Pose bridge: confine "coordinate frame difference" to one token

Critical design decision: Each frame's LiDAR points are expressed in that frame's camera coordinate (depth is distance from that frame's camera). Therefore, pt_A_tok and pt_B_tok live in different coordinate systems. Comparing them directly with cross-attn makes no sense.

pose_emb = PoseMLP(T̂_AB) added to A-side LiDAR tokens shifts "A coordinate point" to a token-space position equivalent to "brought into B coordinate", so to speak. The transformer's token space is high-dimensional, so the FFN / self-attn internally learn to approximate the true rigid transform.

Key: add pose_emb to one side only. Adding the same embedding to both sides leaves relative position unchanged, losing meaning. Reverse direction (B→A) uses pose_emb_BA = PoseMLP(inv(T̂_AB)) added to B's LiDAR tokens. PoseMLP is shared for both directions (same weights, just invert the input).

Cross-frame attention: Q is always LiDAR, KV mixes both modalities

Why Q = LiDAR is inevitable: For the prediction target (Δu, Δv) to be well-defined, Q must have 3D position. If image tokens are Q, only (u, v) is available and depth is ambiguous; the same (u, v) corresponds to entirely different locations for a car at 5 m vs building at 50 m (epipolar ambiguity). LiDAR has (X, Y, Z), so π_B(T̂_AB · P) is a closed function and target is uniquely determined.

Pure image↔image matchers (SuperPoint, LoFTR, etc.) throw this ambiguity downstream to RANSAC / pairwise geometric verification. LiDAR Q closes the ambiguity on the query side.

KV side includes both modalities:

KV_B = concat(pt_B_tok, img_B_tok) # pt alone is too sparse

Using only point cloud as KV means depending solely on LiDAR points in the patch (typically 10-60), resulting in insufficient information. Mixing in 64 image tokens allows both "pull by geometry / pull by appearance". This way, low-texture regions can be covered by nearby LiDAR points, and sparse-LiDAR regions by image.

Output head

raw = proj([ token ‖ uv_hat_01 ]) # (B, N, 5) (Δu, Δv, log σu, log σv, ρ) # gaussian 2D

uv_hat_01 is the hypothesis position projected with T̂_AB (normalized). Passing hypothesis position as reference to the head allows output to be directly interpreted as residual from hypothesis. Final prediction is uv_pred = uv_hat + Δ, supervision is Δ_gt = uv_gt − uv_hat, loss is 2D Gaussian NLL.

Dual projection loss

Output both A→B and B→A in one forward pass, and average both losses:

loss = 0.5 * ( gaussian2d_nll(Δ_AtoB, target_AB) + gaussian2d_nll(Δ_BtoA, target_BA) )

This has more meaning than just doubling training data:

  • Enforce pose_emb symmetry: training pressure drives PoseMLP(T̂) and PoseMLP(inv(T̂)) to be semantically consistent
  • Prevent one-sided overfit: training only A→B risks pose_emb learning unidirectional bias
  • Usable in downstream BA: in production, both directions' residuals can be fed as constraints on a shared pose block

Why short-range training should solve long-range

Core observation: f takes no baseline as input. Therefore f does not know the baseline.

Train f on reliable GT pose at short range (1–5 m), call f at long range (100–200 m) at inference, aggregate many points with BA, and by the law of large numbers, pose estimate converges to GT (as long as f is unbiased out-of-distribution).

Conditions for this to hold:

  1. f is unbiased on long-range input distribution. Fill this gap with scale_emb (inject log(d_B/d_A) into positional encoding) and view-angle augmentation. Systematic bias cannot be saved even by LLN.
  2. Per-point errors are approximately i.i.d. Sampling from spatially distant patches keeps correlation small.
  3. Confidence filter. Only predictions with small σ (high confidence) enter BA. Mixing low-confidence predictions perturbs BA.

Bootstrap loop

What's truly powerful is that the above eliminates the need for GT pose. The following self-supervised loop runs:

stage 0: train on short range (1–5 m) ← public GT is reliable stage 1: apply f to mid range (20–60 m), estimate pose via LLN stage 2: only high-confidence tracks (small σ) → promote to mid-range pseudo-GT stage 3: retrain on short + mid stage 4: same loop on long range (100–200 m) stage 5: retrain on full range → done

Structure similar to progressive self-training like Noisy Student / DROID-SLAM. Bootstrapping with a net that outputs per-point Σ-attached residuals is likely without prior example.

Key findings

  • Multi-scene eliminates overfit: v03 (1 scene) has train-val gap 2.5x, v04 (31 scenes) shrinks to 1.4x. scene count = data diversity was the main driver of train-val gap.
  • Deformable attention is decisive (confirmed numbers):

    • v09 (std 2-layer): val 4.46 px → adding layer +0.12 px (margin of error)
    • v08 (deform sl 2-layer): val 2.87 px → deform adds +1.59 px (35%)
    In other words, deform is 13× more effective than adding layers. Attention mechanism improvement dominates over model depth.
  • val absolute value is true generalization capacity: val 2.87 px is average error on unseen 8 scenes, unseen (fi_A, fi_B) pairs. Achieving this with zero training samples means a scene-independent residual prediction function f has been learned.

🚗 The net learned on its own that "moving cars are unpredictable"

The most interesting part of the visualization:
  • Static structures (buildings, roads, curbs, signs, poles, traffic lights) have small σ, 2σ ellipse is ≲ 1 px → pred ● nearly lands on ★
  • Moving cars have noticeably inflated σ, 2σ ellipse covers several tenths of the patch. Moreover, that ellipse (mostly) contains GT ★. In other words, the model correctly expresses "it may be offset, but we don't know where it offset to".
This was not taught. No dynamic/static labels were provided. Only whether positions match across frames A → B arrives as NLL gradient. When training with NLL, the optimal solution is "if you can't hit it, output large σ" rather than "hit it precisely" — the model found this.

Expected downstream impact:
  • σ-weighted BA automatically down-weights dynamic points (Mahalanobis distance = Δ/σ has σ in denominator). Statistical outlier rejection comes for free, without hard-extracting dynamic detection or semantic segmentation.
  • Thresholding σ to extract dynamic mask yields unsupervised dynamic-object detector as byproduct.
  • At long range like baseline ±40 frames, σ inflates overall (verified in bl40 vis below). BA solver sees this and judges "this pair has low confidence", avoiding large deviations from pose initial value.
Observation: At short range (±5, ±10), green/orange tend to land on blue — model + BA function correctly. At long range (±40), green roughly approaches blue but orange (BA) misses in some cases — area needing improvement in σ weighting or outlier handling fed to BA. per-point prediction is retained as baseline grows (green ≈ blue), but outliers rampage at pose-level aggregation.
Qualitative finding: Prediction error converges to ~1.3 px regardless of perturbation magnitude. This means model's lower-bound performance (precision limit per sample) is around ~1 px, and val's 2.87 px is the result of averaging different (fi_A, fi_B, pivot).
