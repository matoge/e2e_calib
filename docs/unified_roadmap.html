One residual head for
calibration / SLAM / stereo / loop closure.

Take two observations — LiDAR, a camera, any pair — and without telling the network which is which, predict where a 3D point lands in the other one as per-point (Δu, Δv, Σ). Same function, same forward pass, four product lines.

The shared head

f : (image_B patch, 3D point P_A, hypothesis pose T̂_AB) → (Δu, Δv, Σ)

Σ is either 2×2 (uv only) or 3×3 (uvd, from v12 onward). The function does not know what A and B are. Only the data loader decides that, by choosing what to stuff into patch_A, patch_B, and T̂. The network code never branches on task.

The four tasks and their applications

Taskside Aside Bmeaning of T
A intra-frame calibration LiDAR(t) Camera(t) — patch_A and patch_B are the same image LiDAR → Camera extrinsic
B cross-frame residual Cam(t₁) or LiDAR(t₁) Cam(t₂) ego-motion × extrinsic = relative pose between frames
C cross-camera stereo Cam_L(t) + LiDAR depth Cam_R(t) stereo baseline
D long baseline / loop closure Cam(t₁) Cam(t₁ + Δt), large Δt long-range ego-motion, scene possibly changed

Where each task lands as a product

  • A → LiDAR ↔ Camera calibration product: initial calibration and periodic re-calibration in the field. Zero-shot generalization to an unseen sensor pair is the real win.
  • B → general-purpose SLAM front-end: residual source for VO and short-range pose tracking. The σ weights feed downstream BA as Mahalanobis info directly.
  • C → FCM / TPCM — inter-camera consistency: same-time sanity check between two cameras. Can run through LiDAR or camera-to-camera directly, both are the same f.
  • D → HD-map loop closure: align passes minutes to hours apart. Tolerate large σ, let the BA absorb it, bound map drift.

Architecture: the forward is fixed, the data loader varies

forward (CalibNetCrossFrame — models/cross_frame.py): patch_A ──CNN(shared)──► img_tok_A ┐ patch_B ──CNN(shared)──► img_tok_B ┤ │ cross-attn uvd_A ─ PointMLP + frustum ─► Q ───┴──► Q attends to img_tok_B │ ▼ (Δu, Δv, Σ) per query, in B-pixel pose_emb(T̂) → 6-DoF hypothesis concat to each query intra-block SA → per-point self-attn across the query set dual training → (A→B) and (B→A) trained symmetrically

Task branching lives entirely in the Pair Dataset: what it decides to load into patch_A / patch_B / uvd_A / T̂. The network does not care whether T̂ is an extrinsic, ego-motion, or a stereo baseline — the math is the same.

Why this unifies cleanly: the geometric formulation is identical. The image-feature extraction is identical. The only task-specific parts are (1) how each sample is assembled, and (2) the σ distribution in practice. (1) is absorbed by the data loader; (2) can be absorbed by an optional task-id embedding concatenated into pose_emb. Weight sharing is a real upside: the calibration task teaches the backbone to bind LiDAR points to image features, which is exactly what cross-frame needs as well.

Where we are today

Per-task status

  • A intra-frame calibration: legacy head CalibNetDepth (experiments/all_v3_mc/) at val NLL 2.07 (obj 1.06, bg 2.13). Not yet ported to the unified head — this is target #1 of the integration work.
  • B cross-frame: CalibNetCrossFrame (experiments/cross_frame_v13_mix/ through v18_more_visits/). Mixed PandaSet 39 + Waymo 80 scenes, UVD enabled. v18 currently at 1.91 px (21% better than v13's 2.42), with the train/val mean gap cut from 1.40 to 0.74 px.
  • C cross-camera stereo: not started. Only needs a pair-generation script.
  • D loop closure: inherited via B (baselines 1–60 frames already swept at eval time). True cross-drive loop closure has not been tested.

What v18 on B showed

  • Raising per-frame visits from ~25 to ~125 (virtual_epoch 4000 → 20000) dropped val err from 2.42 to 1.91 px (21%).
  • Train/val mean gap was halved. That says the mean head generalizes better with more varied exposure; σ head is still TBD.
  • In other words, at v13–v17 the bottleneck was a kind of scene-level overfit. More data exposure per-scene buys real accuracy, not just epoch-count inflation.
  • The σ calibration question (val NLL trend, z = err/σ) is not yet confirmed — we only looked at val err so far. Checking the NLL curve is the next diagnostic.

Roadmap

Premise: methodological novelty is not the moat. The moat is the in-house pipeline that keeps producing cm-accurate poses and dense 3D maps every day. The milestones below are the shortest path to getting that pipeline covering all four tasks.
MilestoneContentEstimate
M0 Finish v18, inspect σ distribution and val NLL, re-run 3D BA eval (in progress today). today
M1 New PandaSetCalibPair — emits the same sample dict as cross-frame, but for the A task (LiDAR vs same-time camera, perturbed extrinsic). 1 day
M2 MixedPairDataset + --mix-spec CLI flag for weighted sampling across per-task datasets. ½ day
M3 Train v19_ab_mix on A + B together; measure per-task val err / σ. Direct comparison against the old all_v3_mc baseline. ½ day
M4 Implement C stereo pair dataset; train v20_abc_mix. Run an ablation with/without the task-id embedding. 1 day
M5 Company data adapter (CompanyCalibPair). Sub-pixel evaluation against GICP-refined pose — first time we see the actual precision ceiling. 2–3 days
M6 Dedicated D loop-closure evaluation — same street, different drive (and different day if available) pose recovery. 1 day

Total: 5–6 working days. Once M5 lands, every product line (calibration product, SLAM front-end, FCM/TPCM, HD-map loop closure) shares a single trained head.

Risks and open questions

  • σ overfit: v18 softened the mean-side gap, but z = err/σ has to be re-measured. Mixing tasks may re-expose the issue. Light mitigation is post-hoc σ rescaling (~10 LOC). Heavier mitigation is dropout / weight decay on the σ head specifically.
  • Pose-GT ceiling: public datasets (PandaSet, Waymo) carry systematic errors at sub-pixel to 0.5° levels. Our sub-pixel-accuracy claims will be capped by their GT until we swap to the company GICP-refined cache in M5.
  • Per-task σ distribution: calibration and cross-frame see different real-world noise profiles. A task-id embedding in pose_emb should let the head learn one σ scale per task. Not yet tested.
  • NuScenes: currently shelved because its 2 Hz keyframe rate makes baseline_max a 10 sec physical gap, outside the Waymo / PandaSet regime. Re-integratable via the 20 Hz LiDAR / 12 Hz camera sweep data.
