# LiDAR–カメラ外部キャリブレーション — 4 秒で 0.01 度

2026-08-30 / nuScenes / CalibNet2

---

## 何をするものか

LiDAR 点群とカメラ画像から、その 2 つの間の外部パラメータ（6-DOF）のズレを推定する。

- 入力: 画像 1 枚と、そこに投影した LiDAR 点
- 出力: 点ごとの uv オフセット `μ` とその不確かさ `σ`、および各点が 6-DOF に
  どれだけ実効的な情報を足すかの 2×2 情報行列 `W`
- ポーズ自体はネットワークが出さない。`μ` と `W` を **外側の Gauss-Newton** に
  渡して 6-DOF を解く

```
image ──┐
        ├─→ CalibNet2 ─→ μ, σ, W ──→ GN (外側) ──→ δ (6-DOF) + H (6×6)
LiDAR ──┘     (点ごと)                 自由パラメータなし
```

学習の教師は「与えた摂動 δ」。0.5° / 0.20 m の範囲でランダムに与える。画像上では
8〜9 px のズレに相当する。

---

## 結果

held-out 11 シーン（学習に一度も出ていない）、437 フレーム。

| | rot 中央値 | rot 最悪 | t 中央値 | 画像換算 |
|---|---|---|---|---|
| 1 フレーム（0.5 秒） | 0.0247° | 0.290° | 4.9 mm | 0.40 px |
| 4 フレーム（2 秒） | 0.0160° | 0.0594° | 3.7 mm | 0.26 px |
| **8 フレーム（4 秒）** | **0.0128°** | 0.0361° | **3.0 mm** | 0.21 px |
| **16 フレーム（8 秒）** | **0.0096°** | 0.0249° | **2.5 mm** | 0.15 px |

画角 100° / 幅 1600 px なので 1° = 16 px。**入力の 8〜9 px を 0.15 px まで詰める。**

![](_figs/2026-08-30_fusion.png)

**ドリフト検出**: 8 フレーム（4 秒）で 0.03° / 8 mm のズレが 3σ で検出できる。
何分も走る必要はない。

## 3 つの構成要素

### 1. σ と情報行列を分ける

`H = Σ JᵀWJ` の `W` をどこから取るかで結果が変わる。

per-point の `σ` は `gaussian2d_nll` が「その点単独の不確かさ」として教師付けする。
同じ `σ` を BA の `−½logdet H` にも使うと、2 つの損失が同じパラメータを逆向きに
引く。

| | 点の NLL が言うこと | BA が言うこと |
|---|---|---|
| σ | その点の実誤差に合わせろ | 28 窓を足した H が過信だから広げろ |

実際にそうすると σ が 2.28 → 26.4 px（11.6 倍）に膨らみ、点誤差 4.15 → 7.77 px、
rot 0.046 → 0.185° と両方悪化した。

**正しい分離**:

| | 学習するもの | 損失 |
|---|---|---|
| σ | その点が単独で持つ不確かさ | `gaussian2d_nll` のみ |
| **InfoHead** | その点が融合後の 6-DOF に足す**実効**情報 | BA の pose NLL のみ |
| μ | 点の対応 | 両方（共有） |

`--ba-w-source infohead` にすると GN が σ を使わないので、BA の勾配は σ に届かない
（実測: BA path で勾配を受けた 106 パラメータのうち 6 個が `info_head`、σ 出力はゼロ）。

これで **χ²/6 が 3113 → 1.0** に落ちた。σ は 2.28 px のまま動かず、InfoHead 側だけで
校正されている。

### 2. フレーム間は χ² ゲート + 正規方程式の和

`H = Σ JᵀWJ` は各観測が独立という仮定。同一フレームの 28 タイルも、隣接フレームも
独立ではないので、素朴に足すと情報を数えすぎる。

実測（同一重み、28 窓/フレーム）:

| 窓数 N | χ²/6 | | フレーム数 F | 実効 F/k |
|---|---|---|---|---|
| 1 | 0.8 | | 1 | 0.6 |
| 4 | 1.9 | | 2 | 1.0 |
| 8 | 2.2 | | 4 | 1.9 |
| 16 | 6.0 | | 8 | 3.8 |
| 28 | 4.4 | | 16 | **5.2** |

**F=8 までは実効数が `F/2` で伸び、16 で 5.2 に飽和する。** 16 枚集めても 5 枚ぶん。
5 秒間隔まで空けても改善しないので、時間的な近さではなくシーン共通の系統誤差。

外れフレーム対策は χ² ゲート。GT は不要。

```
δ̄ = (Σ Hᵢ)⁻¹ Σ Hᵢ δᵢ
cᵢ = (δᵢ − δ̄)ᵀ Hᵢ (δᵢ − δ̄) / 6  >  3   → そのフレームを落とす   （2 回反復）
```

| F=8 | rot 中央値 | rot 最悪 | χ²/6 |
|---|---|---|---|
| sum | 0.0142° | 0.0299° | 2.62 |
| median | 0.0129° | 0.0392° | 4.52 |
| **gate3** | **0.0128°** | 0.0361° | 2.42 |

**中央値を取るのは損**。良いフレームの重みを捨ててしまう。「弾く」と「足す」を
分けるのが正しい。

### 3. 共分散を過分散係数で割る

`k = χ²/6` を実測して `Σ = (H/k)⁻¹` とする。GLM の quasi-likelihood の
dispersion parameter `φ̂ = X²/(n−p)` と同じ操作。

**F ≤ 8 なら k = 2 固定でよい**（F=1〜8 で 1.6〜2.1）。F=16 で 3.1 に上がる。

### 学習の段階

3 段。各段の held-out 1 フレームでの値。

| 段 | 内容 | rot | t |
|---|---|---|---|
| 1 | 点だけ（BA なし） | 0.1829° | 72.8 mm |
| 2 | 1 窓 BA（W = σ ヘッド） | 0.1716° | 60.5 mm |
| 3 | 28 窓融合 BA（W = InfoHead） | **0.0247°** | **4.9 mm** |

段 2 → 3 で桁が変わる。効いたのは融合そのものと、σ を BA から切り離したこと。

### シーンをまたいだ融合は効かない

外部パラメータは車両固有で不変なので、違うシーンのフレームを混ぜても同じ δ を
推定できる。同一シーン内では実効フレーム数が飽和したので、シーンをまたげば
シーン共通の系統誤差が平均化されて飽和しないはず、と考えて測った。

**そうならなかった。**

| F | mode | rot | t | k | 実効 F/k |
|---|---|---|---|---|---|
| 4 | same（同一シーン連続） | 0.0155° | 3.0 mm | 1.94 | 2.06 |
| 4 | cross（F 個の別シーンから 1 枚ずつ） | 0.0156° | 3.3 mm | 1.97 | 2.03 |
| 8 | same | **0.0095°** | 3.2 mm | 2.23 | **3.59** |
| 8 | cross | 0.0113° | 3.0 mm | 2.72 | 2.94 |
| 8 | mix（F/2 シーン × 2 枚） | 0.0091° | 2.4 mm | 2.06 | 3.89 |
| 16 | same | 0.0085° | 2.2 mm | 2.30 | 6.96 |
| 16 | mix | 0.0072° | 2.4 mm | 2.51 | 6.38 |

`cross` は `same` と同じか悪い。**飽和の原因はシーン共通の系統誤差ではない。**
シーンを変えても同じだけ数えすぎるので、モデル自体のバイアスか
`H = Σ JᵀWJ` の構造的な過信。

F=1（融合していない）でも cross の k が 1.56、same が 1.04 と違う。これはシーン
ごとの難易度のばらつきが加わるためで、融合とは別の要因。

## 分散は本当に縮むか

モデルの申告ではなく、GT との差の標本 sd（MAD ベース、外れに強い版）。

| DOF | F=1 | F=8 | F=32 | 1→32 の縮み | 理想 √32 |
|---|---|---|---|---|---|
| wx | 0.0233° | 0.0099° | 0.0047° | 4.93× | 5.66 |
| wy | 0.0185° | 0.0080° | 0.0035° | 5.33× | |
| **wz** | 0.0515° | 0.0236° | 0.0114° | **4.52×** | |
| tx | 6.4 mm | 2.6 mm | 1.3 mm | 4.92× | |
| tz | 7.5 mm | 2.6 mm | 1.2 mm | 6.25× | |

**実誤差はほぼ √F で縮む。** 「1 フレームぶんの分散から下がらない」わけではない。

例外は **`wz`（yaw）**。フレーム間の追加分散 `τ` がフレーム内 sd と同じ大きさ
（τ/within = 1.02、他は 0.40〜0.69）なので、フレームを増やしても縮みにくい。

## この数字が意味しないこと

**絶対精度ではない。** nuScenes の `calibrated_sensor` を真値として δ を注入し、
それを戻せた量を測っている。nuScenes 自体にバイアスがあれば注入側と評価側の
両方に乗って相殺される。データセット内には比較対象がないので、絶対精度は測れない。

さらに 2 つ、実運用より条件が良い:

- `delta_gt` は GT 対応を**同じ GN** に入れて解いた値。ソルバの系統誤差が相殺される
- LiDAR 点の 3D 位置を真値として使っている。測距誤差・ビーム角誤差は乗らない

一方、**過信はしていない**。点の数から見た限界は 1 窓 150 点 × 28 窓 × 16 フレーム
= 67000 点、点残差 3.6 px / √67000 = 0.014 px。実測 0.15 px はその 10 倍で、理論
限界より悪い側にある。

オラクルなしで決まるのは「一貫性」であって「正しさ」ではない。出荷時に一度
オラクル（ターゲット校正、あるいは hand-eye）で合わせ、その後のドリフトを
この手法で監視する、という使い方になる。

## 使っている既存手法

| 部分 | 名前 |
|---|---|
| 弾く | χ² validation gate（Bar-Shalom、NIS gating。g2o/GTSAM の外れ値除去と同じ） |
| 足す | inverse-variance pooling（fixed-effect meta-analysis。カルマンの測定更新と同式） |
| 割り引く | 過分散補正（GLM quasi-likelihood `φ̂ = X²/(n−p)`）。標本調査の design effect、SLAM の NEES と同じ量 |
| 数えすぎの理論 | composite likelihood の Godambe サンドイッチ情報行列 |
| 未実装の代替 | Inverse Covariance Intersection（Noack et al., Automatica 2017） |

新しいのは、`H` を作る per-point 情報行列をネットワークに学習させている部分だけ。
