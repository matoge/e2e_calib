1. 問題設定: pose 推定と map 商品化

商業的には 2 階層の deliverable が必要:

  • per-frame pose — リアルタイム、 蒸留すれば CPU で動く。 自動運転 / ロボット / AR 全部に効く前提機能
  • persistent map — オフラインで cloud 集約、 高精度点群 + 色 + 意味 タグ。 商品そのもの (HD map, ロボ向け永続 anchor)

両 deliverable の核は pair-net 由来の (μ, Σ) 対応。 Pose は外側 BA で 即時に解け、 Map は (μ, Σ) を world frame に蓄積して polish。 model 側は per-pair correspondence prior を提供する役。

2. 現状の pair-net とその美しさ

各 query は LiDAR 点 P (3D 既知)、 仮説相対 pose で reference frame B に投影 → patch 内 cross-attn → 残差 (Δuv, Σ) を出力:

   query frame A                 reference frame B
   ┌─────────────┐                ┌─────────────┐
   │  patch_A    │                │  patch_B    │
   │  • • • • •  │ ── pair-net ─▶ │  ⊕  μ  Σ    │
   │   queries   │                │  ⊕   ⊕      │
   └─────────────┘                └─────────────┘
   pose_AB_hat に perturbation
pair-net の構造的勝利:
  • matching skip — query は LiDAR 点 = 一意 ID、 「同じ点が向こうのどこか」 探す必要無し。 古典 SfM/SLAM の最大難所を構造で消す
  • pose 仮説で投影 → 残差 = 観測。 対応は 定義 で出る、 探索しない
  • per-pair forward は CPU 蒸留可能
  • (μ, Σ) は古典 BA に直接渡せる、 Σ-weighted GN が真っ当に動く

3. 長距離 baseline での限界

pair (frame_A, frame_B) で baseline が 80 m (10 Hz × 80 frame) 級になると:

  • parallax / occlusion で patch の見た目が大きく違う
  • FoV が狭ければ「frame_A で見えてた特徴の半分が frame_B では枠外」
  • 仮説 pose の誤差が大きく投影 anchor がずれる
  • 同形物体 (ポール / 街路灯 / ガードレール) で対応 ambiguous

典型困難例: ポール-樹のシナリオ

同形ポール 5 本、 背後 5 m に木 (識別可能):

  1. frame_t1: 右から 2 番目 のポールが木の前
  2. 3 m 進んで frame_t2: 右から 3 番目 のポールが木の前
  3. ポールは見た目同一、 木との位置関係だけが手がかり
素朴に pair-only だと: frame_A と frame_B 単独では「同形ポール」を 区別できない。 model は「同じポール」と高確信で誤対応 (Σ 小、 mu 間違い)。 BA は確信高い間違い対応を信じて pose 推定 → drift 増加。 BA は認知層を持たないので、 model が disambiguate していない問題は解けない。

4. 解決方針 4 つの選択肢

案機構proscons
(A) pair-only + 短 baseline 鎖 短 link で pair-net 多回 → 各 pose 推定 → BA で連結 model 変更ゼロ、 短 link で精度高 計算量 N×、 dense FoV 前提、 ポール曖昧 case で対応誤りが連鎖
(B) pair × N + BA で fuse 1 anchor から N ref に独立 pair-net → BA で全 pair output 統合 対称性保持、 既存 model 流用 各 pair が他 frame を見ない → 認知層なし、 ambiguity 残存
(C) 多 frame 同時投入 + 内部 softmax 統合 (本案) 1 transformer に N frame の KV を concat、 RPE bias で frame 間相対 pose 表現、 softmax で全 frame 一括統合 model 内部で disambiguation、 ポール-樹解ける KV 量 × N、 attention コスト線形に増える
(D) DROID-SLAM 系 recurrent dense flow + 微分可能 BA、 学習が BA 経由 SOTA 重い、 real-time 苦しい、 GRU 系で解釈低

(A) は wasteful、 (B) は認知層欠如、 (D) は重すぎ。 採用は (C)。

5. 採用案: 多 frame 同時投入 + 内部 softmax 統合

5.1 機構

                    softmax で N frame 統合
                    ┌──────────────────────┐
                    ▼                      │
   Q (anchor 点 P) ───────► attention ─────┤  next layer (繰り返し)
                              ▲
                              │
   KV_all = concat(KV_B, KV_C, KV_D, ...)
        各 KV token に frame 識別 + 3D 位置情報
        (Q, K) ペアに per-pair pose bias (RPE)

5.2 RPE (Relative Position Encoding) で対称性保持

標準 cross-attention に per-(Q, K) bias を加える:

# 通常 attention
scores = Q @ K.T / sqrt(d)              # (N_q, N_kv)
# multi-frame 拡張: pair pose bias
bias[q, k] = pose_mlp(pose_{frame(q) → frame(k)})    # スカラー
scores += bias
attn = softmax(scores) @ V              # softmax 内で全 frame 統合

これは Shaw+2018, T5 [Raffel+2020], RoFormer 系の RPE と同じ図式。 Q-shift 不要、 KV-shift 不要、 frame ID embed も bias に内包。 各 (i, j) ペアの相対 pose 情報が attention 計算で動的に注入され、 softmax で fusion 完成。

5.3 多層化で段階的 disambiguation

   layer 1: 全 frame 独立 sample → softmax fuse → updated Q1
   layer 2: Q1 から再 attention → softmax fuse → updated Q2
   layer 3: ...

各層で Q が 「全 frame consensus を反映した特徴」 に進化。 ポール-樹 ケースは layer 跨いで disambiguate される: layer 1 で「木は安定 anchor」、 layer 2 で 「木相対のポール位置」、 layer 3 で「frame ごとに違うポール」 と段階的に解像度が上がる。

5.4 効率版: level=frame deformable

N が大きい (5+) 場合、 full attention は KV メモリが N 倍に膨らむ。 sample-based の deformable [Zhu+2020] を使い、 各 (Q, frame_i) で 4-8 offset だけ sample:

  • spatial_shapes に N frame の (H, W) を並べる (= 各 frame を level として)
  • reference_uv_i = π(pose_A→i, P) で per-frame anchor
  • softmax over (frame × n_points) で統合 — 機能的に full attn と同じ、 軽量

計算量 O(N_q × N × n_points) で N に線形、 KV concat の重さなし。 PETR/PETRv2 [Liu+2022/2023] の temporal warping 方式と違い、 frame を独立 level として 保持し、 attention が consensus を作る点が key (PETRv2 は pose-warp で時間を消す)。

6. 位置情報の入れ方 — 相対情報のみ

絶対 3D 座標は 絶対に入れない。 入れると model が scene 固有座標 (東京 / SF / 大阪 etc.) を学習してしまい、 scene 跨ぎの汎化が壊れる。 pair-net の 美しさは relative pose だけ で動くこと。 multi-frame 化でもこの原則を保つ。

側位置情報絶対? 相対?encoding
Q (frame_i 内の点) frame_i 内のローカル uv (or uvd で正規化 [0,1]) frame ローカル (絶対座標ではない) PointMLP(uvd_in_local)
KV (frame_j の token) frame_j 内のローカル uv frame ローカル 2D PE on image feat
(Q, K) bias frame_i → frame_j の 相対 6-DoF pose 相対のみ pose_mlp(pose_{i→j}) → スカラー bias

各 token は「自分は frame ローカル uv X です」 と宣言、 frame 間の橋渡しは (Q, K) ペアごとの相対 pose bias のみ。 これは NLP の RPE (Relative Position Encoding [Shaw+2018, T5 [Raffel+2020]]) を 3D pose に拡張した 形そのもの。 frame_id の絶対 index も embedding に出てこない、 必要ならば相対 pose の magnitude / direction で暗黙区別できる。

6.1 PETR 系 (絶対 3D) との対比

PETR / PETRv2 [Liu+2022/2023] 系は逆の哲学:

  • 各 camera image pixel を ego frame の絶対 3D ray に逆投影 → position embedding として feature に加算
  • multi-camera 統合は absolutized 3D 空間で attention
  • temporal は過去 feature を ego motion で warp して現 frame の絶対 3D に揃える

これは scene 固有 (per-sample) の絶対座標を毎回計算するため学習は安定するが、 camera intrinsics calibration の精度依存が高く、 同一 scene 内 detection に最適化された設計。 mapping のように scene 横断 (世界中の道路で同じ model) を求める我々には不向き。

PETR 系 (絶対)本案 (相対のみ)
position embeddingego frame 絶対 3D rayframe ローカル uv のみ
frame 間統合絶対空間での pose-warp + concat相対 pose bias を attention に注入
scene 跨ぎ汎化scene-specific 校正に依存scene 不変 (相対のみ)
主用途3D detection (per-scene)mapping / SLAM (scene 横断)

6.2 pair (N=1) と multi-frame (N≥2) の統一

pair-net 現状: q_A = pt_A_fused + pose_emb_AB ← Q を 事前 shift する形。 これは「Q を K の frame に持ち込む」 操作で、 数学的に attention bias と等価:

# 等価変換
版 A (現 pair-net): score = (Q + pose_emb_AB) @ K.T
版 B (RPE bias):    score = Q @ K.T + (pose_emb_AB @ K.T) ※ K に依存しない部分は内積に吸収
                    ≈ Q @ K.T + b(pose_AB)

multi-frame では K が複数 frame に跨ぐので、 K ごとに pose_emb が異なる → 事前 Q-shift だと K の数だけ Q を複製する羽目になり非効率。 RPE bias 形式 (score += b(pose_{frame(q) → frame(k)})) なら 1 つの Q で済み、 N≥2 でも自然に拡張可能。 pair (N=1) はこの bias 形式の特殊ケースで等価。

結論: 絶対座標は token にも attention 計算にも一切入れない、 全ての frame 間 情報は (i, j) 相対 pose bias 経由でのみ流す。 これで pair から multi-frame まで 連続的に同じ機構で扱え、 scene 不変 / 軽量 / 美しい。

7. depth-optional モード (LiDAR / radar / stereo / mono / none)

商用展開で sensor 構成は車両ごとに違う。 同一モデルで全部対応:

センサdepth 精度 (σ_d)主な顧客層
LiDAR (VLS-128 / Luminar)±2 cm dense自動運転 OEM、 MMS
radar (4D imaging)±10-30 cm sparse、 雨天 robustADAS、 低価格車両
stereo±5 cm 近距離、 距離依存ロボット、 中価格車両
mono + 学習 depth±20-50 cm、 scale ambig低価格、 過去資産映像
カメラのみ (depth なし)—レガシー、 AR

7.1 統一表現

各 query 点を (uv, μ_d, σ_d, has_d) の 5 値で渡す。 sensor 種別は σ_d の値で表現:

σ_d = sensor_sigma(sensor_type, depth)
    LiDAR  : 0.02 m
    radar  : 0.20 m
    stereo : 0.05 m × (depth/30)²
    mono   : 0.30 × depth
    none   : ∞ (has_d = 0)

7.2 学習時の modality dropout

sample ごとに確率的に depth を抜く / σ_d を変える:

if rng.random() < p_drop_d:
    σ_d = INF; has_d = 0       # vision-only sample
else:
    σ_d = sensor_sigma(...);   has_d = 1

PointMLP は (uv, μ_d, σ_d, has_d) の 5 ch 入力

FrustumLocalEncoder の box filter は has_d=0 のとき depth 軸を無視、 UV 軸のみで 近傍判定。 depth 不在分 Σ_uv は自然に広がる方向に学習される。

7.3 多 frame 化との合せ技

depth 完全に欠ける場合、 reference_uv_i は 1 点でなく epipolar 線 になる (depth の 1 自由度が解けないため)。 実装案: depth prior (例 1-80 m) で 3-5 個 sample anchor を線上に並べ、 deformable の n_levels を frame × depth_bin に拡張。 LiDAR ありなら depth_bin = 1、 なしなら 4-5。

多 frame 観測の triangulation で depth ambiguity が消える → Σ_d 縮む = ベイズ更新が attention 内部で起こる。 これは GS 系の view consistency と本質同じ、 ただし per-scene 最適化なし、 feed-forward でやり切る点が違う。

8. 動的物体への拡張

3D bbox tracks (nuScenes/AV2/Waymo の annotation) を per-LiDAR-point ラベルに展開:

  • 各 query 点に is_dynamic, track_id, box_pose_t1, box_pose_t2 を付与
  • 動的点の reference_uv_i は ego pose ではなく box pose で投影
  • 静的点と動的点で同じモデル、 異なる pose hint だけ与える
  • BA 側: 動的点は per-object pose graph factor、 静的点は ego-pose factor → joint 最適化

model 構造は変えない。 reference_uv 計算と BA factor 構築のみ拡張。 データセット側は box→点 ラベル展開 helper を 100 行程度で書く。

9. BA の役割 — 認知でなく統合

BA を model の中に入れない (= DROID 流) 設計の意味:

  • 認知 (disambiguation) = transformer 内部 — softmax fusion + multi-layer 反復で多 frame consensus を構築、 ambiguous な対応は Σ 大で reflect
  • 統合 (pose 6-DoF 抽出) = 1-step BA — 既に disambiguated な (μ, Σ) の Σ-weighted Gauss-Newton で全観測を融合、 計算量 O(N_q × N) で軽量

これにより model は 「観測を上手く出す機械」、 BA は「最適推定を引っ張り出す機械」 と 責務分離。 BA が複雑な対応問題を解こうとしないので失敗パターンが少ない。

なぜ pair-only + iterative BA では駄目か: 短 baseline pair を多数連結して BA で stitch する案 (上記 (A)) は理論上動くが、 (1) 都市環境の繰り返し模様で個々の pair 対応が ambiguous で BA が drift、 (2) 短 link 多用で計算量 O(N²)、 (3) 狭 FoV / 隠蔽で連鎖切断、 などで品質保証困難。 multi-frame transformer + 1-step BA はこれら全部を内部 softmax で吸収する。
