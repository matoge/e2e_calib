実験 Progression — 何を学ぶ／何を凍結する

方針: ベース学習 (full train) はデータセットを変えた時だけ。 それ以外の架構拡張 (extension) は fine-tune で、新しく追加した部品だけを学習する。 これでイテレーションを高速化する。

1. モジュール台帳 (どこに何があるか)

毎ステージで どの state_dict prefix を凍結するか を厳密にするため、 モデル構成を以下に固定する。

役割state_dict prefix役職
画像エンコーダcnn.*ConvNeXt or CNN backbone — patch → coarse feature
点エンコーダpoint_mlp.*(u,v,d) → D-token
frustum 局所frustum_enc.*近傍 LiDAR 集約
intra-frame 融合intra_blocks.*concat(pt, img) self-attn (per-frame)
Q-shift posepose_mlp.*Q ← Q + pose_mlp(pose_AB)。 attention 直前に Q を pose 方向にずらすことで、 pair モードでも cross-attn に明示的 pose 信号を入れる。 (per-frame KV bias のみだと pair モードで softmax が定数を打ち消し効果ゼロ — そのための補完)
per-frame KV biaspose_bias.*cross-attn scores に per-(Q-frame, KV-frame) スカラー 加算。 pair (KV=1 frame) では定数なので無効化。 multi-frame (KV=M‖B) で M↔B の選択を pose 距離に応じて gate
cross blockscross_blocks.*N-frame KV 連結 + per-frame bias 付き cross-attn → self-attn → FFN → 出力 head。 pair = N=1 KV、 multi-frame = N≥2 KV の特殊化

「cnn + point_mlp + frustum_enc + intra_blocks」をまとめて frame encoder と呼ぶ。これがデータ依存の部分で、 ステージ拡張ではここを凍結する。

3. 凍結の実装フック

python train_cross_frame.py \
    --multi-frame \
    --init-from experiments/cross_frame_v50_ps39_baseline \
    --name v51_finetune \
    [...]

--init-from の動作 (実装中):

  1. best_model.pt を strict=False でロード
  2. マッチした key (frame encoder + pose_mlp) はコピー
  3. マッチしなかった key (新しい cross_blocks, pose_bias) はランダム init のまま
  4. cnn, point_mlp, frustum_enc, intra_blocks, pose_mlp の requires_grad=False
  5. optimizer は filter(lambda p: p.requires_grad, model.parameters()) で構築

Sanity check: 学習開始時のパラメータ数ログを「総数 / 学習対象」で出すこと。 たとえば S1 では 1.514M total / 0.31M trainable になる想定。

4. ステージごとの「成功基準」

段階比較対象成功とみなす条件
S0 v50v42 (PandaSet 109)val_err ≤ 3.0 px on PS39 front
S1 v51v50val_err 同等 (±0.2 px) または 長 baseline (≥30 frame) で val_err 改善
S2 v52v51radar/stereo/mono データで val_nll 健全 (≤4.0)、 LiDAR-only が劣化しない
S3 v53v52動的物体上の σ が静止物体の 2-3× に拡大 (識別できている)
S4 v54v53chain N=4 で N=2 (v53) より val_err 改善

5. 重要な不変条件 (どの段階でも崩さない)

  • Q と KV の token は 自分のフレーム local の uv しか持たない (絶対 3D を流し込まない)
  • pose 情報は RPE bias として attention scores に加算するだけ (Q-shift 旧式は legacy)
  • frame encoder の重みは凍結後も同じ data 分布 (PandaSet 系) で使い続ける限り再学習不要
  • データセットを混ぜる (S2 で stereo / mono を入れるとか) 場合は modality dropout で LiDAR-only ベースラインが回帰しないことを毎評価
進め方の本筋:
S0 を一度しっかり作る → 以降は extension を 1 個ずつ fine-tune で乗せる。 データを変える時だけ S0 から作り直す。 これで毎エポック数十分 → 数分のオーダーで イテレーションできるはず。
