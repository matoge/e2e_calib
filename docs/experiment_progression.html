Experiment Progression — What to Learn / What to Freeze

Policy: base training (full train) is done only when the dataset changes. All other architectural extensions are handled via fine-tune, training only the newly added components. This keeps iteration fast.

1. Module Registry (What lives where)

To make which state_dict prefix to freeze unambiguous at every stage, the model composition is fixed as follows.

Rolestate_dict prefixFunction
Image encodercnn.*ConvNeXt or CNN backbone — patch → coarse feature
Point encoderpoint_mlp.*(u,v,d) → D-token
Frustum localfrustum_enc.*Neighborhood LiDAR aggregation
Intra-frame fusionintra_blocks.*concat(pt, img) self-attn (per-frame)
Q-shift posepose_mlp.*Q ← Q + pose_mlp(pose_AB). By shifting Q in the pose direction immediately before attention, an explicit pose signal is injected into cross-attn even in pair mode. (With per-frame KV bias alone, in pair mode the softmax cancels the constant and the effect is zero — this fills that gap.)
Per-frame KV biaspose_bias.*Adds a per-(Q-frame, KV-frame) scalar to cross-attn scores. In pair (KV=1 frame) it is constant and therefore ineffective. In multi-frame (KV=M‖B) it gates the M↔B selection based on pose distance.
Cross blockscross_blocks.*N-frame KV concatenation + cross-attn with per-frame bias → self-attn → FFN → output head. Pair = N=1 KV, multi-frame = N≥2 KV specializations.

We call the bundle "cnn + point_mlp + frustum_enc + intra_blocks" the frame encoder. This is the data-dependent part and is frozen during stage extensions.

3. Freezing Implementation Hooks

python train_cross_frame.py \
    --multi-frame \
    --init-from experiments/cross_frame_v50_ps39_baseline \
    --name v51_finetune \
    [...]

Behavior of --init-from (in progress):

  1. Load best_model.pt with strict=False
  2. Copy matched keys (frame encoder + pose_mlp)
  3. Unmatched keys (new cross_blocks, pose_bias) remain at random init
  4. Set requires_grad=False on cnn, point_mlp, frustum_enc, intra_blocks, pose_mlp
  5. Build the optimizer with filter(lambda p: p.requires_grad, model.parameters())

Sanity check: log the parameter count at training start as "total / trainable". For example, S1 is expected to show 1.514M total / 0.31M trainable.

5. Key Invariants (never broken at any stage)

  • Q and KV tokens carry only their own frame-local uv (no absolute 3D is fed in)
  • Pose information is only added to attention scores as an RPE bias (the old-style Q-shift is legacy)
  • As long as the same data distribution (PandaSet family) is used, the frame encoder weights need no retraining after being frozen
  • When mixing datasets (e.g., adding stereo / mono at S2), verify at every evaluation via modality dropout that the LiDAR-only baseline does not regress
Main flow of the approach:
Build S0 solidly once → then stack extensions one at a time via fine-tune. Only rebuild from S0 when the data changes. This should shrink iteration time from tens of minutes to minutes per epoch.
