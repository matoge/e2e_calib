3.1 Confluence の macro-parser 誤爆パターン

Confluence の HTML マクロ内に入れても、"外側" の wiki-markup パーサが先に文字列を舐めて {name param} 形のトークンをマクロ呼び出しと誤認してしまう現象が2系統。

コードリスト{train.log, best_model.pt, ...}Macro train.log, ... unknown&#123;/&#125; エンティティで回避

3.2 publish_wiki_to_confluence.py update の double-escape 事故

raw storage XML (<ac:structured-macro>...<ac:plain-text-body><![CDATA[...]]></ac:plain-text-body></ac:structured-macro>) を update に渡すと、内部で wiki-markup 変換を通過することがあり、CDATA が round-trip で破壊される。 Confluence 側では本文全体が &lt;ac:structured-macro... のように実体参照化された状態で保存され、 ページを開くと HTML タグが文字列としてそのまま表示される (= "タグ丸見え")。

再発防止: storage XML を直接差し替える時は curl -X PUT /rest/api/content/{id} に body.storage.representation="storage" の JSON を投げる。これなら変換器を素通りする。 publish_wiki_to_confluence.py には手を入れない (ユーザー指示)。 
payload = {
  'version': {'number': N+1},
  'type': 'blogpost',
  'title': '...',
  'body': {'storage': {'value': body_raw, 'representation': 'storage'}}
}
# → curl -s -X PUT -H "Authorization: Bearer $TOKEN" \
#     -H "Content-Type: application/json" \
#     --data-binary @payload.json \
#     https://confluence.tri-ad.tech/rest/api/content/$ID

3.3 画像と本文のミスマッチ

新規ブログ作成時の二段階公開 (create with placeholder → upload attachments → PUT で URL 差替え) は正解だが、 upload する画像自体が間違っていると placeholder 置換が成功しても中身はズレる。 今回は deform 記事に attention_order の画像を上げてしまい、本文と完全不一致。

再発防止: 記事の body HTML 書き出し直前に、参照する画像パスと記事のトピックが一致するかを明示的に チェックする段取りにする。将来的には publish_report_blog のような関数に、記事 ID と この記事が 許可する画像ファイル名プレフィクスをセットで渡す運用。

§ 5 ゼロショット可視化 (中断中、再開の準備はできてる)

ゴール

キレイにキャリブされた Woven シーケンス (ip654_...1749030654176-1749030664176) で、 アノテーション付きの物体·背景を crop し、現行の学習済み CalibNetDepth が UV 補正をどう出すか を矢印で描画する。摂動 0° と 1° 程度の小角 extrinsic を両方見る。

摂動の意味

ユーザー発言: "節度１度とか、せつどうとかあたえなくてもずれてるゆあつあるから"。
つまり摂動ゼロでも既にずれている可能性がある、ということ。 ゼロでも矢印が系統的に一方向を向けば 現状キャリブのバイアスの証拠になり、 1° かけたときに予測が −δ 方向を指せば モデルが正しく補正を出している 証拠になる。

投影公式 (loom backend から確認済)

# projection_utils.py:165-284
R_camera_to_vehicle = Rotation.from_euler('zyx', [yaw, pitch, roll]).as_matrix()
R_to_rdf            = [[0,-1,0],[0,0,-1],[1,0,0]]                      # axis swap
R_total             = R_to_rdf @ inv(R_camera_to_vehicle)
mp_total            = -R_total @ fcm.mp

# POSLV adjust
R_poslv, mp_poslv   = from_euler(poslv.rot_zyx), poslv.mp
R_rear2cam          = R_total @ R_poslv
t_rear2cam          = R_total @ mp_poslv + mp_total

# project
p_cam = R_rear2cam @ p + t_rear2cam    # filter z > 0
uv    = cv2.fisheye.projectPoints(p_cam, 0, 0, K_kb4, [k1,k2,k3,k4])

§ 8 ディスカッション — このセッションで学んだこと

8.1 コミュニケーションで詰まった箇所

"いや、キャリ部とかじゃないどころのPOCができたんだよ みてくれ"

ここで最初 "Phase-Only Correlation" の続きを探してしまい空振り。 教訓: 略語の候補が複数ある場合 (POC = Phase-Only Correlation / Proof of Concept) は、 最新の git log --since で "feat" 系のコミット差分から当てにいく方が速い。

"さいきんの３つとか４つとかのれこみっとみれない？"

ユーザーは常に 直近コミット差分から話を始めたがっている。 これ以降、話題が変わったらまず git log --oneline -N を打って最新差分を先に読む習慣を定着させる。

"おまえいまどこにいるんだ？"

pwd を定期的に出す。リポジトリを跨ぐ作業 (loom ↔ e2e_calib) では bash -c 'cd ... && ...' で 明示的に指定し、勘違いの余地を減らす。

8.2 Confluence との付き合い方

Confluence の storage format + wiki-markup マクロパーサは、見た目が普通の HTML でも 特定のトークン列で勝手にマクロ呼び出しとして解釈するという性質を持つ ({...} 等)。 これは CDATA 内でも完全には抑制されないことがあり、コードサンプルの波カッコや CSS の一行ブロックが地雷になる。

対策として以下を恒久ルール化:

  • storage 書き込みは必ず REST PUT 直叩き (converter を経由させない)。
  • コードリスト内の {...} は &#123;...&#125; に事前エスケープ。
  • CSS ルールは一行化しない (一行の {...} もマクロに化ける)。
  • 本文を POST/PUT する前に、本文文字列に対して 禁止パターンの lint を自動でかける (将来 TODO)。

8.3 新規ブログ公開の安全手順

  1. 本文 HTML をローカルに保存 (/tmp/page_<name>.new.html)。
  2. POST で新規ブログを作る (placeholder を含んだまま)。pageId が採番される。
  3. その pageId に attachments を upload (画像ファイル名と記事トピックが一致するかを必ず目視確認)。
  4. 本文中の placeholder を https://confluence.tri-ad.tech/download/attachments/<pageId>/<fname> に置換して PUT。
  5. GET で body.storage.value.startswith('<ac:structured-macro') と '&lt;ac:structured-macro' not in body を必ず検証。

8.4 ハブと進捗可視化

今回のようにレポートが増えてくると、どれを見に行けばいいかわからない 問題が発生する。 docs/hub.html に左ナビ + iframe + ハッシュディープリンクを用意したので、今後は新しい *_report.html を書いたらナビに1行足すだけで共有できる。URL は http://172.18.2.49:5080/hub.html#<file>。
