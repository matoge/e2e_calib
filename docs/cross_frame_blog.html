A Single Residual Head for Calibration, VO, and Loop Closure

LiDAR 3D —— camera images —— hypothesis pose —— learn a single function — "where does this 3D point land in another frame?" — and calibration / VO / loop closure / BA all collapse into the same call.

The core idea. LiDAR produces 3D point clouds, cameras capture synchronized images, and vehicle pose is linked by ego-motion. Where a point P_A appears in frame B is purely a geometric projection problem if the pose is correct. In practice, pose is never perfect, so residuals emerge. If we can learn a function that predicts this residual, all geometric problems—calibration / VO / long-baseline loop closure / BA—collapse into the same function call.

This article documents how we trained that function f with 1.59M parameters on PandaSet 31 train / 8 val scenes (scene-level split) to achieve val 2.61 px, and how uncertainty σ automatically inflates on dynamic objects without any explicit supervision.

Problem Setup: f is baseline-agnostic

We train a single function f:

f : (image_B patch, 3D point P_A in frame A, hypothesis pose T_AB_hat) → (Δu, Δv, Σ) s.t. π_B(T_AB_gt · P_A) = π_B(T_AB_hat · P_A) + (Δu, Δv)

The concept of baseline never appears in the input. Whether A and B are 1m or 200m apart, f receives the same input type. This property makes all existing tasks special cases of f:

  • LiDAR↔Camera calibration: A=B (same frame), T_AB = extrinsic ± perturbation
  • VO (consecutive frames): T_AB = frame t → t+1, perturbation = dead-reckoning error
  • Loop closure: A and B are 100–200m apart, perturbation = map-relative error
  • Long-range relocalization: pose difference from prior map
How this differs from prior work (and where we stand).
Image-only matchers (LoFTR, RoMa, MASt3R) face an inherently under-determined correspondence problem—the same pixel could belong to a car 5m away or a building 50m away (epipolar ambiguity). They defer this to downstream RANSAC / geometric verification.
We have LiDAR 3D points as input, so π_B(T_hat · P_A) is a closed-form function, and the ambiguity is eliminated from the start. The network only needs to learn "residuals from geometrically determined points" instead of "ambiguous correspondences."

On the other hand, the structure of conditioning on pose and emitting updates is shared with BA-Net / DROID-SLAM / DPVO refiners. The differences are (a) LiDAR+camera instead of image-only, (b) explicit per-point covariance Σ output for hybrid design that feeds into Ceres BA, (c) f is baseline-agnostic so the same network handles calibration / VO / loop-closure. LCCNet / CalibNet / RGGNet use the same LiDAR+camera input but only regress "one extrinsic per frame" and do not handle per-point residuals or T≠I.

How Pairs are Constructed: Critical Correctness Checks

One training pair = (patch_A, patch_B, uvd_A, uvd_B, T_AB_hat, Δ_target). From PandaSet's 39 scenes, we use 31 train scenes and randomly sample: scene → frame_A → pivot 3D point → baseline 1–20 frames for frame_B. T_AB_hat = T_AB_gt · δT (σ_ypr=1°, σ_t=0.2m) adds dead-reckoning-level perturbation.

Critical correctness design: During training, patch_B is cropped centered on the hypothesis projection π_B(T_hat · P_A)—not the GT projection. If we centered on GT, the answer would always fall at the patch center, causing self-supervised leakage that breaks training.

Architecture: One Asymmetry Holds Everything Together

Shared CNN + PointMLP for both frames, concat for modality fusion via self-attn, then cross-attn directly connects frame A ↔ B. Simple. But we introduce one asymmetry:

Q = LiDAR token (3D position → π uniquely determines target) KV = concat(LiDAR, image) — can be indexed by either geometry or appearance pose_emb = PoseMLP(T_AB_hat) — added only to frame A LiDAR tokens

Why Q must be LiDAR—For (Δu, Δv) target to be well-defined, the query side must have 3D position. If image tokens were Q, we'd only have (u, v), and depth ambiguity would resurface: the same (u,v) could be a car 5m away or a building 50m away (← the Achilles heel of image matchers mentioned earlier). LiDAR Q closes this ambiguity on the query side.

pose_emb added to one side only—Adding the same embedding to both sides doesn't change relative position. For the reverse direction (B→A), we add PoseMLP(inv(T_hat)) to frame B LiDAR tokens, and the loss is symmetric in both directions—dual projection loss. This prevents one-sided overfitting and enforces semantic symmetry in pose_emb.

Output is a 5D 2D Gaussian (Δu, Δv, logσu, logσv, ρ). In v12 (described later), we expand to 7D (Δd, logσd added) to include depth, but UV accuracy doesn't degrade.

Results: val 2.61 px, Deformable Attention is the Deciding Factor

PandaSet 31 train scenes / 8 val scenes (scene-level split, seed=42 for deterministic shuffle). Baseline 1–20 frames, σ_ypr=1.0°, σ_t=0.2m, img_size=64, max_points=256, 60 epochs. ~6 minutes per run on RTX 5080. The 8 val scenes are never seen during training—a true scene-level generalization test.

Interesting Byproduct: σ Spontaneously Inflates on Dynamic Objects

We apply the trained model to val pairs at bl = ±5 / ±10 / ±20 / ±40 frames, and visualize each query point's prediction (Δu, Δv, Σ) as "prediction• + 2σ covariance ellipse":

This was never taught. We provided no labels for dynamic vs. static objects. Only whether projections match between A ↔ B arrives as NLL gradient. Under NLL training, the optimal solution is "if you can't hit it, output large σ" rather than "always try to hit it sharply"—the model discovered this on its own.

Expected downstream benefits:
  • σ-weighted BA automatically down-weights dynamic points (Mahalanobis distance Δ/σ has σ in the denominator). Statistical outlier rejection comes for free, without hardcoding dynamic-object detection or semantic segmentation externally.
  • Thresholding σ to cut out dynamic masks yields an unsupervised dynamic-object detector as a byproduct.
  • On long-range pairs, σ inflates overall (see bl40 below)—the BA solver can judge this pair as low-confidence.
This is naturally acquired purely from NLL, unlike SuperGlue's matchability or RoMa's confidence head, which require separate "outlier filter" learning.

f is Baseline-Agnostic ⇒ Bootstrap Loop Spins Up

Core observation: f does not take baseline as input. Therefore, f is baseline-agnostic. Train f on reliable GT pose at short range (1–5m), then at inference call f on long range (100–200m), and aggregate many points in BA—by the law of large numbers, pose estimation converges to ground truth—as long as f is unbiased out-of-distribution.

stage 0: train on short-range (1–5m) ← public GT is reliable stage 1: apply f to mid-range (20–60m), estimate pose via LLN+BA stage 2: only high-confidence tracks (small σ) → mid-range pseudo-GT stage 3: retrain on short + mid stage 4: same loop for long-range (100–200m) stage 5: retrain on all ranges → done

The structure resembles progressive self-training from Noisy Student / DROID-SLAM lineage. The difference is bootstrapping via a network that outputs per-point residuals with Σ—Σ can be directly used for "high-confidence track extraction" at stage 2.

Three closest works:

  • DROID-SLAM (Teed & Deng, 2021)—recurrent iterative refinement of pose + depth. The "take pose as input and emit Δ" structure is shared. Differences: input (image-only vs LiDAR+image), explicit covariance, network doesn't hold BA but passes to traditional Ceres. DROID's training distribution strongly assumes video-rate, and long-range loop closure is handled separately.
  • LCCNet (Lv et al., 2021)—regresses LiDAR↔camera decalibration 6-DoF via cost volume. Same sensor setup, but only outputs "one pose per frame" and doesn't handle per-point residuals or baseline≠0. This work can be seen as LCCNet generalized to per-point × arbitrary baseline.
  • BA-Net (Tang & Tan, 2019)—feature-metric BA, the originator of the "embed geometry prior into network" philosophy. We replace depth basis with LiDAR, narrow the learning target to Δ + Σ, and leave BA itself in Ceres for a hybrid design. Network is lightweight at 1.59M params, rig/dataset-agnostic.

Summary and Next Steps

  • Current state: PandaSet 8 val scenes, val 2.61 px, deform attention + UVD head, σ naturally inflates on dynamic objects.
  • Next bottleneck: BA translation improvement is negative. Test whether incorporating v12's Δd as BA's 3D constraint (Mahalanobis w/ diagonal depth σ) can rescue t.
  • Scale up: Add NuScenes / Waymo (Waymo has per-segment 0.2° pose GT error, so treat as auxiliary). PandaSet 39 → hundreds of scenes.
  • Ablation using σ as dynamic filter: Hard reject σ > θ vs soft weight 1/σ², which is more effective for BA?
  • scale_emb: Inject log(d_B/d_A) into positional encoding for long baseline. Also explore recurrent form that feeds v12's Δd back into input.
