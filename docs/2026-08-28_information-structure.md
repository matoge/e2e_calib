# 2026-08-28 — 情報構造の測定：どこまでが分散で、どこからが精度か

[2026-08-28_grouped-ba-infohead.md](2026-08-28_grouped-ba-infohead.md) の続き。
「なぜ 0.1 度にならないのか」を、理屈ではなく全部測った記録。

## 結論

| 問い | 測定結果 |
|---|---|
| 分散は校正できているか | **できている**。`InfoHead` の予測 sd は経験共分散の 0.75〜1.21 倍 |
| ロールアウト（複数フレーム学習）は要るか | **要らない**。経験共分散を取れば真の情報量は分かる |
| なぜ 0.1 度に届かないか | **ωx 0.18° / ωz 0.16° の全フレーム共通バイアス**。分散ではなく精度の問題 |
| 窓を増やせば下がるか | **下がらない**。28 窓で `1/√N` 理論値 0.189 に対し実測 0.447 |
| 数百点は必要か | **不要**。貪欲 D 最適の 16 点で全点 2470 点の 1.18 倍 |
| フル画像は計算が通るか | **通る**。1600×900 で 83 ms / 1.85 GB（256 クロップ 28 枚は 73 ms / 1.17 GB） |

## 1. 真の情報量 — 経験共分散

各フレームで `e = δ̂ − δ_gt`（6 要素）を集めて標本共分散を取る。`H⁻¹` が予測すべきものそのもの。

**厳密版**（1 フレーム固定、δ を 40 通り引き直す、8 フレーム）：

| frame | ωx (emp/pred) | ωy | ωz | tx | ty | tz |
|---|---|---|---|---|---|---|
| 0 | 0.2298/0.2042 | 0.0290/0.0251 | 0.2178/0.1633 | 0.0088/0.0075 | 0.0272/0.0330 | 0.0078/0.0077 |
| 4 | 0.2427/0.2037 | 0.0342/0.0256 | 0.2347/0.1843 | 0.0089/0.0075 | 0.0222/0.0339 | 0.0079/0.0078 |
| 7 | 0.2568/0.2226 | 0.0416/0.0299 | 0.2427/0.2466 | 0.0097/0.0091 | 0.0200/0.0350 | 0.0083/0.0082 |

比 0.75〜1.21。**分散はもう合っている。**

予測 sd 自体のフレーム間ばらつきは p90/p10 = 1.05〜1.36 でほぼ一定。

## 2. 2 つの不確かさヘッドは別物

```
per_pt[..., 2:5] (log_sx, log_sy, rho)  <- gaussian2d_nll  (点ごとの loss)
InfoHead2x2 -> W                        <- 融合ポーズ NLL のみ
```

同じ残差（p50 6.327 px）に対して：

| ヘッド | σ_u | σ_v | 点の Mahalanobis²（校正 2.0） | ポーズ eHe/6（校正 1.0） |
|---|---|---|---|---|
| `per_pt[2:5]` | 2.745 | 8.425 | **1.0346** | **136.380** |
| `InfoHead2x2` | 49.507 | 535.629 | 0.0018 | **1.228** |

**点ごとの σ は正しく出ている**（Mahalanobis² 1.03）。それを独立と仮定して足した瞬間に 136 倍過信になる。
`InfoHead` は逆に、点レベルの意味を捨てて σ を膨らませ、足した後だけ合わせている。

窓内残差の共通成分は **84%**。`InfoHead2x2` は点ごとの 2×2（完全ブロック対角）しか出せないので、
この相関を表現する場所がそもそも無い。

## 3. バイアス vs ノイズ

同じ δ を 60 フレームに掛け、誤差をフレーム平均（共通バイアス）とばらつきに分解（6 通りの δ）：

| DOF | \|フレーム平均\| | フレーム間 sd | bias/sd | sd/√60 |
|---|---|---|---|---|
| **ωx** | **0.18235°** | 0.11081° | **1.65** | 0.01430° |
| ωy | 0.01084° | 0.02452° | 0.44 | 0.00317° |
| **ωz** | **0.15855°** | 0.14677° | **1.08** | 0.01895° |
| tx | 0.00428 m | 0.00663 m | 0.65 | 0.00086 m |
| ty | 0.01255 m | 0.02161 m | 0.58 | 0.00279 m |
| tz | 0.00447 m | 0.00637 m | 0.70 | 0.00082 m |

ωx と ωz はバイアス支配。フレームを 60 個足しても sd 側は 0.014°/0.019° まで落ちるが、
バイアス 0.18°/0.16° は残る。**0.1 度に届かない中身はこれ。**

## 4. フレーム間融合は過信する（後段の統計では直らない）

同じ δ を N フレームに掛けて情報和：

| N | CONSEC rot / eHe | SPREAD rot / eHe |
|---|---|---|
| 1 | 0.4298° / **0.983** | 0.4728° / 1.577 |
| 4 | 1.7254° / 173.2 | 1.3257° / 116.0 |
| 40 | 0.5329° / **833.0** | 0.1663° / **805.4** |

別シーンから集める（SPREAD）と誤差は下がる（0.53 → 0.17°）が、**過信量は変わらない**（833 vs 805）。

後段で直そうとしたもの（すべて失敗）：

| 方法 | rot | eHe/6 |
|---|---|---|
| 情報和 | 0.306° | 847.19 |
| 変量効果（対角 τ, DerSimonian-Laird, in-sample） | 0.307° | 38.33 |
| 変量効果（フル 6×6 τ, in-sample） | 0.309° | 36.78 |
| 変量効果（フル 6×6 τ, held-out） | 0.295° | 16.90 |
| Covariance Intersection（フレーム間） | 0.792° | 116.5 |
| Covariance Intersection（点レベル） | 0.706° | 0.112（N_eff が 1.0 に崩壊） |
| 射影整合 Σ（`Jᵢ Σ Jᵢᵀ = Wᵢ⁻¹` の最小二乗） | 0.245° | 0.008 |

フル 6×6 τ は対角とほぼ同じ（36.78 vs 38.33）→ **軸間共分散では説明できない**。
点レベル CI は `logdet` が 1 点に寄って崩壊（各 `Hᵢ` がランク 2 のため）。

## 5. 窓・点をいくら増やしても飽和する

**窓数 vs 誤差**（1 フレーム内、GRID / RANDOM）：

| 窓数 | GRID vs N=1 | RANDOM vs N=1 | 理論 `1/√N` |
|---|---|---|---|
| 1 | 1.000 | 1.000 | 1.000 |
| 4 | 0.938 | 0.688 | 0.500 |
| 16 | 0.518 | 0.634 | 0.250 |
| 28 | **0.447** | **0.615** | **0.189** |

**1 窓が張る方向数**：H の固有値（正規化）は `1.46e-05 / 1.15e-04 / 8.32e-04 / 3.83e-03 / 1.50e-02 / 1.00e+00`。
1e-3 を超えるのは **6 自由度中 3.0 方向**。窓あたりの点数は **2〜4 点で飽和**（1→2 で 1.457→1.162、105 点で 1.00）。

**点の選び方**（1 フレーム 2470 点、全点 = 0.2449°）：

| 上位 K | NET (leverage) | GEOM (W=I) | GREEDY (D 最適) |
|---|---|---|---|
| 8 | 0.7082° | 0.8953° | **0.3444°** |
| 16 | 0.4104° | 0.9181° | **0.2897°** |
| 256 | 0.2604° | 0.6114° | 0.3336° |

貪欲 **16 点で全点の 1.18 倍**。leverage の単純ソートは同じ方向の点ばかり選ぶので効かない。
上位 32 点が持つ情報は全体の 23.7%。

理論的背景：leverage は hat matrix の対角、貪欲 `logdet` 最大化は **D-optimality**（Fedorov 交換）。
`logdet` は劣モジュラなので貪欲解は最適の `1−1/e` 以内。

## 6. GT なしでキャリブレーション誤差は検出できるか → この測り方では不可

δ を掃引して `|μ|`（モデルが GT なしで出す予測ずれ）を見た：

| ε (pitch) | \|μ\| px | \|duv_gt\| px | μ/duv_gt |
|---|---|---|---|
| −0.5 | 12.4827 | 12.1413 | 1.0281 |
| −0.1 | 4.6843 | 2.4200 | 1.9356 |
| **0.0** | **4.0449** | **0.0026** | 1545 |
| +0.1 | 4.7536 | 2.4180 | 1.9659 |
| +0.5 | 12.6866 | 12.1648 | 1.0429 |

`|μ|` は `|duv_gt|` をなぞっているだけで、**ε=0 の谷はキャリブレーションの正しさを意味しない**
（摂動が小さいほど残差が小さいだけ）。ε=0 での `|μ| = 4.04 px` がモデルの残差フロア。

軸ごとの応答傾き（1.0 = 完全に検出）：**pitch −0.976 / yaw −0.724 / roll −0.219**。
**256px クロップからは yaw と roll がほとんど観測できていない。** これがバイアス ωx/ωz の中身。

1. **フル画像 1 段目 + パッチ 2 段目**
   1 パッチは 6 自由度中 3 方向しか張らないので、残り 3 方向をプライアで押さえる。
   粗い段（フル or 低解像度）の `H` をそのままパッチ段の `prior_diag` に渡す。

   「フレーム対 → カメラ対」の振り替えでそのまま使える。

### `vfp` は calib 経路で使われていない（が、これはバグではない）

`pandaset_full.py:1780` で `vfp = fx * S / cs` を計算し `collate_full` が渡し、
`CalibNet2.forward` の引数にもあるが、calib 経路は受け取るだけで一度も使わない
（`forward_frame` に渡していない）。使うのは `forward_cross_frame` の
`PoseEmb.intrinsic_mlp(log_vfp)` だけ。

ただしこれは問題ではない。ネットワークは「この点と画像特徴がローカル画素で何 px ずれているか」
を出すだけで、原画素への変換は GN 側が `s2o = cs / img_size` と `K_orig` で行う
（`vfp = fx / s2o` と同じ情報を別の形で持っている）。スケール不変な問題設定になっている。

**検証**（S9 をクロップ可変で実行、6 窓・共通 δ `|ypr| 0.5315°` / `|t| 0.2835 m`）:

| クロップ | 実 cs | rot 誤差 | t 誤差 | 融合 |
|---|---|---|---|---|
| 256 固定 | 256 × 6 | 0.0000〜0.0003° | 0.0001 m | rot 0.0000° / t 0.0001 m |
| 256..768 | 288, 460, 530, 309, 418, 464 | 0.0000〜0.0001° | 0.0000〜0.0001 m | rot 0.0000° / t 0.0001 m |

### ClearML の debug 画像は `va_mse` と別集合

`va_mse 4.5` も両方正しく、**別のものを見ている**。

### `va_mse` は平均（中央値ではない）

```python
err = (per_pt[valid][..., :2] - gt[valid]).norm(dim=-1)
total_mse += err.mean().item()
```
ただし外れ値のせいではない。最悪 1% の寄与は train 8.2% / val 7.9% で同じ。
分布全体がずれている（p50 1.247 → 2.396、p90 3.858 → 11.399）。

## 追記 (深夜): 摂動が world 系だった — 並進と複数フレームの結果はすべて無効

`_build_one_window` の摂動:

```python
R_off  = R_gt @ Rotation.from_euler('zyx', ypr)   # 右から掛ける = CAMERA 系
cp_off = cp + t_delta                              # world のカメラ位置に足す = WORLD 系
```

**同じ 2 行で座標系が混ざっていた。** 回転は偶然カメラ系で正しく、並進だけ world。
キャリブレーション誤差はカメラ・LiDAR 間の固定変換なので、両方カメラ系でなければならない。

### 症状

`pert_const`（全フレームに同じ δ）で 40 フレームの `δ_gt` を測ると:

| | wx | wy | wz | tx | ty | tz |
|---|---|---|---|---|---|---|
| std（修正前） | 0.0000 | 0.0000 | 0.0000 | 0.0252 | 0.0049 | **0.1136** |
| std（修正後） | 3e-6 | 1e-5 | 1e-5 | 4e-5 | 3e-6 | 6e-5 |

摂動 0.2 m に対し、**車の向きが変わるだけでカメラ系の並進が 0.11 m 動いていた**。
つまり「同じ δ を N フレームに掛けて融合する」は、違う量を足していた。

`P_off = R_d^T (P_gt - R_gt^T t)` （t が world）→ `R_gt` 依存
`P_off = R_d^T (P_gt - t)`         （t がカメラ系）→ フレーム不変

cross-frame 経路（`build_pair`, line ~1170）は最初から `cp_B + R_gt_B @ t_delta` とカメラ系で
書かれていた。calib 経路だけが world だった。

### 直した構造

`build_crop` の中で world を一度で捨てる:

```python
pts_cam = (pts_c - cp) @ R_gt              # カメラ原点へ、1 回だけ
R_d = R_gt.T @ R_off ;  t_d = R_gt.T @ (cp_off - cp)
pts_cam_off = (pts_cam - t_d) @ R_d        # 原点をずらす／回す
pts_cam_orig = pts_cam[sub_idx]            # 再変換なし
dist_m = norm(pts_cam[sub_idx])
```

S9 が完全一致になった（world 経由の数値誤差も消えた）:

| | fit px | rot err | t err | 融合 |
|---|---|---|---|---|
| 修正前 | 0.0005〜0.0027 | 0.0000〜0.0002° | 0.0001 m | rot 0.0000° / t 0.0001 m |
| 修正後 | **0.0000**（6/6） | **0.0000°** | **0.0000 m** | **rot 0.0000° / t 0.0000 m** |

### 無効になった結果

- 並進の軸別分解すべて（tx/ty/tz はフレームごとに違う軸に乗っていた）
- 複数フレーム融合すべて（`eHe/6` の N 依存、N=16 上限、CI / 変量効果 / MAX 系の比較、
  bias/sd、収縮 k、SPREAD vs CONSEC）

### 注意: `pert_vec` のラベルが実際と入れ替わっている

`Rotation.from_euler('zyx', ypr)` に `[a,b,c]` を渡すと z→a, y→b, x→c。カメラ系では
z 軸まわり = roll、y 軸まわり = yaw、x 軸まわり = pitch なので、`pert_vec[3:6]` を
「yaw, pitch, roll」と呼んでいるのは実際には **roll, yaw, pitch**。実測 uv 変位:

```
ypr=[0.5,0,0] -> du 0.92  dv 0.49   (roll)
ypr=[0,0.5,0] -> du -12.49 dv -0.05 (yaw)
ypr=[0,0,0.5] -> du 0.05  dv 11.36  (pitch)
```

ソルバー側の `DOF6 = (omega_x, omega_y, omega_z)` はカメラ軸まわりなので正しい
（ωx=pitch, ωy=yaw, ωz=roll）。ずれているのは `pert_vec` のラベルと、それを表示する
掃引スクリプトだけ。
